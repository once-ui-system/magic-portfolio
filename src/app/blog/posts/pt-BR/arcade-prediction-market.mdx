## Visão Geral Técnica

Os mercados de predição permitem que os usuários negociem com base no resultado de eventos futuros. Este post examina a implementação arquitetônica e matemática do **Arcade**, uma Prova de Conceito (PoC) de mercado de predição implantada na **Arc Testnet (Circle L1)**. O sistema utiliza um Formador de Mercado de Produto Constante (CPMM) para fornecer liquidez contínua, contratos inteligentes escritos em Solidity, um indexador customizado em Node.js para rastreamento de eventos e uma interface Next.js com tema cyberpunk.

## Arquitetura do Sistema

A arquitetura da plataforma foi projetada para lidar com negociações com latência mínima, garantindo que os detalhes de portfólio dos usuários e os preços dos mercados sejam atualizados em tempo real.

```text
[Cliente Web3] ──(Negocia Cotas / Deposita USDC)──> [Smart Contracts Solidity]
       │                                                     │
(Consultas API)                                        (Emite Eventos)
       │                                                     │
       ▼                                                     ▼
[Next.js Frontend] <──────(JSON-RPC de Alta Velocidade)────── [Node.js Indexer]
```

## 1. Mecânica do Formador de Mercado Automatizado (AMM)

Nos mercados de predição tradicionais baseados em livro de ofertas, eventos de baixo volume podem sofrer com falta de liquidez e spreads altos. O Arcade resolve isso utilizando um **Formador de Mercado de Produto Constante** (<LatexRenderer>{`x \\\\cdot y = k`}</LatexRenderer>) para facilitar trocas de cotas contínuas e instantâneas.

Dentro de cada pool de predição:
*   <LatexRenderer>{`x`}</LatexRenderer> representa a reserva de cotas de **SIM** (YES).
*   <LatexRenderer>{`y`}</LatexRenderer> representa a reserva de cotas de **NÃO** (NO).
*   <LatexRenderer>{`k`}</LatexRenderer> é o produto constante.

### Colateralização e Emissão de Cotas
Todas as posições são totalmente colateralizadas por USDC. Quando um usuário deseja comprar cotas:
1.  O usuário deposita <LatexRenderer>{`1`}</LatexRenderer> USDC no contrato.
2.  O contrato emite <LatexRenderer>{`1`}</LatexRenderer> cota de SIM e <LatexRenderer>{`1`}</LatexRenderer> cota de NÃO (respaldadas por <LatexRenderer>{`1`}</LatexRenderer> USDC).
3.  Dependendo da predição do usuário, um tipo de cota é devolvido ao usuário e o outro tipo é vendido para o pool de liquidez da AMM para manter a invariante do produto constante.

### Cálculos de Preço
O preço de mercado de cada resultado representa a probabilidade implícita de o evento ocorrer. O preço de uma cota de SIM é calculado a partir das reservas de ambos os resultados:

<LatexRenderer displayMode>{`\\text{Preço}_{\\text{SIM}} = \\frac{y}{x + y}`}</LatexRenderer>

À medida que os usuários compram cotas de SIM, as reservas de SIM do pool diminuem e as reservas de NÃO aumentam, deslocando automaticamente o preço para cima para refletir a nova demanda do mercado.

## 2. Padrão Factory & Contratos em Solidity

Para permitir a criação sem permissão de novos mercados de predição, o sistema implementa uma estrutura de contrato Factory. Isso desacopla o registro de implantação da lógica de pools individuais.

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "./PredictionMarket.sol";

contract MarketFactory {
    address[] public allMarkets;
    address public immutable usdcToken;

    event MarketCreated(address indexed marketAddress, string question, uint256 endTime);

    constructor(address _usdcToken) {
        usdcToken = _usdcToken;
    }

    function createMarket(string calldata question, uint256 endTime) external returns (address) {
        PredictionMarket newMarket = new PredictionMarket(question, endTime, usdcToken, msg.sender);
        allMarkets.push(address(newMarket));
        emit MarketCreated(address(newMarket), question, endTime);
        return address(newMarket);
    }
}
```

Cada contrato `PredictionMarket` é responsável por:
*   Garantir cálculos de derrapagem (slippage) e limites de troca.
*   Custodiar o colateral de USDC de forma segura.
*   Distribuir os pagamentos aos vencedores após a resolução do mercado pelo proprietário.

## 3. Testes de Invariantes via Foundry Fuzzing

Como os pools baseados em CPMM dependem de cálculos de divisões e multiplicações matemáticas na máquina virtual da Ethereum (EVM), erros de arredondamento poderiam potencialmente resultar em perda de fundos. Implementamos **testes de fuzzing** no Foundry para validar as invariantes do AMM sob valores arbitrários de transação.

```solidity
function testFuzz_CPMM_Invariants(uint256 buyAmount) public {
    // Restringe os inputs gerados para faixas realistas de transação
    vm.assume(buyAmount > 100 && buyAmount < 1_000_000 * 10**6);
    
    // Armazena a invariante k pré-transação
    uint256 initialK = market.x() * market.y();
    
    // Executa a transação simulada
    vm.prank(user);
    market.buyYesShares(buyAmount);
    
    // Valida que o produto constante final não diminuiu
    uint256 finalK = market.x() * market.y();
    assertGe(finalK, initialK, "Invariante do produto constante violada!");
}
```

## 4. Indexação de Eventos em Tempo Real

Para exibir gráficos interativos de flutuação de preço e a lista de portfólios atualizada, a aplicação utiliza um indexador Node.js personalizado. Fazer consultas diretas na RPC do blockchain para logs históricos é ineficiente.

O indexador:
1.  Escuta logs de swap e criação emitidos pelos nós RPC da Arc L1.
2.  Analisa e armazena os dados em um banco de dados local.
3.  Fornece rotas de API otimizadas que servem dados históricos de volume e trajetórias de preço para o frontend.
