## Cálculo de Recompensa

A fórmula fundamental de recompensa captura vários relacionamentos importantes:

<LatexRenderer displayMode>{`r = \\frac{v \\cdot s \\cdot a}{T} \\cdot d`}</LatexRenderer>

onde
- $r$ é o valor das recompensas não penalizadas;
- $v$ é o volume de swap diário (em USD);
- $s$ representa as recompensas de staking;
- $a$ representa o valor em stake (em USD);
- $d$ representa o número de dias em que ESSE VALOR esteve em stake;
- $T$ é o valor total em stake no pool (em USD).

Isso mostra que as recompensas escalam com:
1. O uso do protocolo (volume)
2. A proporção do seu stake em relação ao pool
3. O tempo comprometido

A implementação em Python traduz esta fórmula em código enquanto lida com casos extremos:

```python
def compute_usd_rewards(days, amount, pool):
  # Calcula a parcela do usuário no pool
  proportion = amount / pool.total_amount
  
  # Calcula as recompensas diárias com base no volume e taxa de recompensa
  daily_reward = proportion * pool.daily_swap_volume * pool.staking_rewards
  
  # Escala pelo número de dias em stake
  return daily_reward * days
```

Para recompensas denominadas em KDX, simplesmente convertemos do USD usando o preço atual:

```python
def compute_kdx_rewards(days, amount, pool, kdx_price):
  # Obtém as recompensas em USD e converte para KDX
  usd_rewards = compute_usd_rewards(days, amount, pool)
  return usd_rewards / kdx_price  # Preço atual do KDX em USD
```

Esta abordagem em duas etapas nos permite:
1. Calcular recompensas em termos de USD estáveis primeiro
2. Converter para tokens KDX voláteis em seguida
3. Ajustar facilmente para flutuações de preço

```python
def compute_usd_rewards(days, amount, pool):
  proportion = amount / pool.total_amount
  return proportion * pool.daily_swap_volume * pool.staking_rewards * days
```

Então nós convertemos isso em KDX:

```python
def compute_kdx_rewards(days, amount, pool, kdx_price):
  return compute_usd_rewards(days, amount, pool) / kdx_price
```

## Lógica de Penalização: Protegendo Stakers de Longo Prazo

O sistema de penalidades tem dois propósitos principais:
1. Desencorajar o staking de curto prazo tipo "bater e correr" (hit and run)
2. Recompensar liquidez comprometida de longo prazo

A porcentagem de penalidade segue uma curva de potência inversa:

```python
def compute_penalty_percentage(days, pool, coefficient):
  # Calcula os dias restantes para a maturidade
  rem = pool.required_days - days
  
  # Aplica a fórmula da curva de potência se ainda estiver no período de penalidade
  return (rem / pool.required_days) ** coefficient if rem >= 0 else 0.0
```

Características principais:
- Começa com 100% de penalidade no dia 0
- Diminui suavemente à medida que a maturidade se aproxima
- Cai para 0% após os dias necessários (60)
- O coeficiente (0.66) controla a inclinação da curva

Em seguida, calculamos o valor real da penalidade:

```python
def compute_usd_rewards_penalty(days, amount, pool, coefficient):
  # Calcula recompensas potenciais
  potential = compute_usd_rewards(days, amount, pool)
  
  # Aplica a porcentagem de penalidade
  return potential * compute_penalty_percentage(days, pool, coefficient)
```

E o equivalente em KDX:

```python
def compute_penalized_kdx_rewards(days, amount, pool, coefficient, kdx_price):
  # Obtém o valor penalizado em USD
  usd_penalty = compute_usd_rewards_penalty(days, amount, pool, coefficient)
  
  # Converte para KDX
  return usd_penalty / kdx_price
```

## Ajustes no Período de Espera

Quando um usuário adiciona mais dinheiro ao pool, o novo tempo de espera é calculado por:

<LatexRenderer displayMode>{`\\frac{t\\times n + r\\times p}{n+p}`}</LatexRenderer>

onde
- $t$ é o tempo de maturação
- $r$ é o tempo de espera anterior (posição do usuário na curva de penalidade);
- $p$ é o valor anterior em stake;
- $n$ é o valor recém-adicionado ao stake.

Implementação em Python:
```python
def update_waiting_period(added_amount, previous_amount, days_to_maturity, pool):
  import math
  return math.ceil((pool.required_days * added_amount + days_to_maturity * previous_amount) / (added_amount + previous_amount))
```

## Curva de Penalidade: Desincentivo Ponderado pelo Tempo

A penalidade aplicada às recompensas diminui gradualmente conforme os stakers se aproximam da duração necessária de staking. Isso cria uma queda no estilo sigmoide que:

1. Desencoraja fortemente saídas antecipadas
2. Fornece recompensas crescentes à medida que o compromisso continua
3. Aproxima-se de zero penalidade na maturidade total

A representação matemática usa a fórmula:

<LatexRenderer displayMode>{`\\Big(\\frac{D-d}{D}\\Big)^c`}</LatexRenderer>

onde
- $D$ é a quantidade de dias necessários para ter 0 penalidades;
- $d$ é o número de dias desde que o usuário fez o stake;
- $c > 0$ é um coeficiente arbitrário.

Nota: O usuário receberá (1 - porcentagem de penalidade) das recompensas

![Curva de Penalidade](/images/blog/staking/penalty_curve.png)

**Principais Insights:**
- Primeiros 30 dias: ~90% de penalidade (forte efeito de retenção - lock-in)
- Dias 30-50: Rápida diminuição da penalidade
- Após o dia 60: Penalidade quase nula (recompensas totais)

## Modelando a Interação do Usuário

A simulação acompanha três métricas principais ao longo do tempo:
1. **Acumulação de recompensas** - Como as recompensas crescem com o tempo
2. **Progressão de maturidade** - Como a janela de penalidade diminui
3. **Retornos líquidos** - Combinando o principal e recompensas após penalidades

```python
def simulate_period(days, inputs, pool):
   d = 0
   no_input_days = 0
   rewards_list = []
   maturity_list = []
   penalized_amounts_list = []
   days_to_maturity = pool.required_days
   amount_penalty_days = AMOUNT_PENALTY_DAYS
   amount = 0
   
   while d <= days:
     # Lida com novos depósitos
     pool.total_amount += inputs[d]
     if inputs[d] > 0 and d >= 1:
       days_to_maturity = update_waiting_period(inputs[d], amount, days_to_maturity, pool)
       amount_penalty_days = AMOUNT_PENALTY_DAYS
       no_input_days = 0
     
     amount += inputs[d]
     no_input_days += 1
     
     # Aplica a penalidade do principal se estiver na janela de penalidade
     if no_input_days <= 3:
       penalized_amounts_list.append(0.97 * amount)
     else:
       penalized_amounts_list.append(1.0 * amount)
     
     # Atualiza a contagem regressiva para a maturidade
     if days_to_maturity > 0:
       days_to_maturity -= 1
     
     d += 1
     rewards_list.append(compute_usd_rewards(1, amount, pool))
     maturity_list.append(days_to_maturity)
   
   return rewards_list, maturity_list, penalized_amounts_list

def compute_cumulative_rewards(rewards_list):
  import numpy as np
  return np.cumsum(rewards_list)
```

Principais visualizações da simulação:

1. **Recompensas Acumuladas** - Mostra o crescimento linear das recompensas não penalizadas
2. **Dias para a Maturidade** - Acompanha a contagem regressiva para as recompensas totais
3. **Recompensas Penalizadas** - Mostra as recompensas reais após as penalidades
4. **Retornos Líquidos** - Combina principal e recompensas penalizadas

## Juros Compostos Semanais: Maximizando Retornos

A composição semanal reinveste as recompensas de volta no principal a cada 7 dias, criando um crescimento exponencial:

```python
def simulate_weekly_compounding_period(days, inputs, pool):
   d = 0
   no_input_days = 0
   rewards_list = []
   maturity_list = []
   penalized_amounts_list = []
   days_to_maturity = pool.required_days
   amount = 0
   
   while d <= days:
     pool.total_amount += inputs[d]
     if inputs[d] > 0 and d >= 1:
       days_to_maturity = update_waiting_period(inputs[d], amount, days_to_maturity, pool)
       no_input_days = 0
     
     amount += inputs[d]
     no_input_days += 1
     
     # Aplica a penalidade principal se estiver dentro da janela
     if no_input_days <= AMOUNT_PENALTY_DAYS:
       penalized_amounts_list.append(0.97 * amount)
     else:
       penalized_amounts_list.append(1.0 * amount)
     
     if days_to_maturity > 0:
       days_to_maturity -= 1
     
     d += 1
     rewards_list.append(compute_usd_rewards(1, amount, pool))
     maturity_list.append(days_to_maturity)
     
     # Lógica de composição semanal
     if d % 7 == 0:
       # Reinveste as recompensas da última semana
       days_to_maturity = update_waiting_period(
         np.sum(rewards_list[-7:]), 
         amount, 
         days_to_maturity, 
         pool
       )
       amount += np.sum(rewards_list[-7:])
       no_input_days = 0
   
   return rewards_list, maturity_list, penalized_amounts_list
```

Principais benefícios dos juros compostos semanais:
- As recompensas começam a render suas próprias recompensas
- Retornos 11,2% maiores que o staking simples
- Melhor eficiência de capital mantendo a liquidez

## Estimativa de APR/APY

Calcula os retornos anualizados para diferentes estratégias de composição:

```python
def calculate_apr_apy(pool, comps):
  days = 365
  res = {}
  inputs = [0 for _ in range(days + 1)]
  inputs[0] = 1  # Começa com $1 no stake
  
  for comp in comps:
    # Simula um ano completo
    rewards, maturity, _ = simulate_regular_compounding_period(
      days, inputs, pool, comp
    )
    cumulative_rewards = compute_cumulative_rewards(rewards)
    
    # Calcula o valor final penalizado
    final_rewards = cumulative_rewards[-1] * (
      1 - compute_penalty_percentage(
        60 - maturity[-1],
        pool,
        KDX_COEFFICIENT
      )
    )
    
    res[comp] = final_rewards
  
  return res
```

Os resultados mostram os retornos anuais para:
- Sem composição: 22,87% 
- Composição semanal: 25,64% (+11,2%)
- Composição mensal: 25,19% (+9,1%)

**Principais Conclusões:**
- A composição semanal (7 dias) fornece retornos ~11,2% maiores do que sem composição
- A composição mensal (60 dias) fornece retornos ~9,1% maiores do que sem composição
- Uma composição mais frequente leva a retornos melhores, mas exige mais transações


## Implicações Econômicas e Estratégicas

Nossas simulações de staking revelam dinâmicas econômicas importantes:

**Efeitos no Nível do Protocolo**
- A curva de penalidade reduz a pressão de venda durante o staking inicial
- O alinhamento de longo prazo melhora a estabilidade do pool
- As recompensas compostas criam ciclos de feedback positivo

**Considerações dos Participantes**
1. **Stakers de Varejo**
   - Composição semanal ideal para a maioria dos usuários
   - Saques antecipados extremamente caros
   - Saldos menores se beneficiam da paciência

2. **Participantes Institucionais** 
   - Podem otimizar os cronogramas de composição
   - Beneficiam-se mais de recompensas baseadas em volume
   - Têm recursos para monitorar a maturidade

**Benefícios Sistêmicos**
- Cronogramas previsíveis de emissão
- Menor volatilidade do suprimento bloqueado
- APRs sustentáveis que se ajustam às condições do mercado

1. **O Compromisso de Tempo Importa**  
   A curva de penalidade cria fortes incentivos para o staking de longo prazo, com recompensas aumentando drasticamente após a metade do período.

2. **Juros Compostos Amplificam os Retornos**  
   Nossas simulações mostram que a composição periódica (semanal vs mensal) pode aumentar os retornos líquidos em 5-15% em relação ao staking simples.

3. **Alinhamento do Protocolo**  
   Este design alinha os incentivos do usuário com a saúde do protocolo - os stakers de longo prazo se beneficiam mais, criando uma liquidez mais "grudenta" (retida).

4. **Considerações Estratégicas**  
   - Saídas antecipadas são pesadamente penalizadas (tanto principal quanto recompensas)
   - A frequência ideal de composição depende do seu horizonte de tempo
   - O tamanho e o volume do pool impactam diretamente os seus retornos
